## real-usage-remediation-roadmap

Turned the field evaluation in Z_REPORT_REAL_USAGE_ANALYSYS.md into a code-grounded remediation plan, written to ROADMAP_IMPROVE_REAL_USAGE.md. Verified every claim in the report against v1.2.0 source before planning: found the read path exceeds its own token budget (this session: 6065 estimated vs 4000 budget), discards priority when a query is given, has no BM25 in either read tool, and never excludes ignored directories from keyword search. Also discovered the report's Cursor blocker is stale — Cursor now ships stable lifecycle hooks, which opens a mechanical fix for the .ai-memory write-protocol violations rather than instruction-only bans. Plan is organized as phases R0-R7 with per-item code references, acceptance criteria, effort, and a release mapping (1.2.1 / 1.3.0 / 1.4.0).

**Key decisions:**
- Sharpened the report's 'BM25 has no IDF' finding: there is no BM25 at all. keyword_search does zero ranking (first max_results matches in filesystem order) and context uses TF over log doc-length. The fix is to build the shared ranker that was assumed to exist, not to add IDF to an existing one.
- Prioritized R0 (make the token budget honest) ahead of the large indexed read path, because five localized fixes in context.py/search.py remove the over-budget bug agents hit every session with no new dependencies or file formats.
- Elevated Cursor hooks (R2) to position 2 in execution order, ahead of the retrieval rewrite: it is fully independent work, now unblocked, and preToolUse/beforeReadFile can deny raw file-tool writes into .ai-memory/ with an explanatory agent_message — converting the loudest instruction-only rule into a mechanism.
- Sequenced map auto-regeneration on store write (R3-1) as a hard prerequisite for maps-first startup context (R1-3): making maps the primary context surface while they can only be refreshed by dreaming would turn cosmetic rot into a load-bearing failure.
- Accepted breaking the 'never slice a file mid-document' invariant for oversized episodic files only (R0-4), to be recorded as an ADR rather than done silently — the invariant protects prose coherence, and a journal that silently evicts the architecture map is the worse failure.
- Chose stdlib sqlite3 in gitignored .ai-memory/private/ for the frontmatter index (R1-1), with graceful fallback to today's full-scan path, preserving the zero-dependency-core and local-first guarantees.
- Recommended building the retrieval_quality eval harness (R6-1) alongside R0 rather than at the end, since eval currently scores only store hygiene and cannot fail on a retrieval regression — without it none of the read-path work is provable.
- Gated the coding-memory benchmark (R6-3) behind R0-R1, since publishing numbers against today's read path would measure the bug rather than the design.
