## merge-conflict-free-memory

Fixed the reported multi-developer merge conflicts in `.ai-memory/` (`failures.md`, `index.md`, and a shared episodic day file). Reproduced the exact conflict set first, then addressed all three causes: the half-installed merge driver (per-clone registration nobody re-ran), generated views being textually merged despite being rebuilt from the store every Dream, and the driver's pure-append-only body merge. Added `ai-memory resolve-conflicts` for teams already mid-merge. 26 merge-driver tests (up from 11), ruff and mypy clean, no new failures in the suite.

**Key decisions:**
- Generated maps union-merge and are re-stamped (`body_hash` recomputed, `store_fingerprint` blanked) — without the re-stamp `regenerate_maps` folds the merged union into `memory-store/` as a permanent memory
- Block-level (`##`) merge replaces the pure-prefix-append requirement; block text is compared with trailing blank lines stripped so an untouched block does not look edited on the branch that appended after it
- `resolve-conflicts` reads the index stages rather than parsing conflict markers, so it is exact and never has to redo the merge
- Union merging delegates to `git merge-file --union` for correct anchoring, with a pure-Python fallback
- The driver now takes git's `%P`; old registrations keep working because `index.md` is also recognized from frontmatter
